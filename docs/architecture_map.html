Active Frontend Flows

Server Actions → Service → Prisma

1. Register & Login Flow

1. Client → auth.action.ts register()
2. Server Action calls POST /api/auth/register (NestJS)
3. Response: ApiResponse<{accessToken, refreshToken, user}>
4. Sets httpOnly cookies, returns success
5. Router redirect to /group

2. Token Refresh Flow

1. http.client.ts receives 401
2. Calls POST /api/auth/refresh with refresh token
3. Returns new accessToken; retries original request
4. On failure → clear cookies, redirect to /auth

3. Family Tree Sync Flow

1. Client (Redux draft) → family.action.ts
2. Server action → PUT /api/family/:groupId/sync-family
3. Backend transaction update (family + members + rels)
4. Returns updated data
5. Redux dispatch syncSuccess

4. Frontend Module Dependencies

Core libraries:
lib/prisma.ts lib/prisma-errors.ts api/http.client.ts api/api-client.lib.ts api/fetch-with-auth.ts middleware/auth.lib.ts env/env-config.lib.ts res/response.factory.ts
Store slices:
family/ user/ blog/

Client ↔ Backend API Communication

REST · /api prefix · ApiResponse envelope

Request Path

1. Next.js Server Action ("use server") → api-client.lib.ts
2. http.client.ts fetch wrapper → http://localhost:3000/api/...
3. NestJS Controllers (global /api prefix, CORS enabled)
4. Guards: AtGuard (JWT) → RolesGuard / GroupLeaderGuard
5. Response via ResponseFactory: { statusCode, message, data }
6. Errors mapped: Prisma errors → domain errors (both lib/prisma-errors.ts và common/errors)

Auth & Session

· Access + refresh tokens in httpOnly cookies (Next.js)
· Backend stores refresh token in Session (device-based, unique userId+userAgent)
· proxy.ts middleware: auth check, RBAC, silent refresh
· OAuth: Google via AuthProvider + Verification state rows
· Auth audit: AuthLog (type LOGIN | REGISTER | PASSWORD)
